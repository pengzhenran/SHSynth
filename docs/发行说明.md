**三条主线:多时间批量处理、水平形变 u_N/u_E、FFT 经度快路径。**

| 新增 | 一句话 | 实测 |
| --- | --- | --- |
| **时间轴** `shsynth.timeaxis` | 系数/场知道自己对应哪一天;文件名三规则 + gfc 头清洗;缺测/重复只报告 | 203 个真实 gfc 对 legacy `*_TimeInfo.dat` 最大误差 **4.6e-07**(≤1e-6) |
| **序列读取** `series-read` | 一个 `GSM-*.gfc` 目录 → 带日期的 `(L+1,L+1,N)` 序列;混入 GAC/GAD 报错 | 203 个文件 0.5 s 读完 |
| **序列落盘** `series_nc` / `series_dat` | `.nc(time,n,m)` 契约(与 SHKit 对齐);legacy 三角 `.dat` 双向 | 往返**逐位**;legacy 文本按它的 ~9 位有效数字对表 |
| **写盘带时间坐标** | `write_grid(times=)` / `read_grid(with_time=True)`:修掉"写出即丢日期" | 写→读日期逐值一致;`3_grids` 257 个历元读得回 |
| **批量综合** `series-synth` | 整条序列一次算完;逐历元诊断表;可疑历元 MAD 离群**只报告不剔除** | 一次算完 ≡ 逐历元循环(≤1e-12) |
| **FFT 经度快路径** | 整圈均匀经度上把逐点经度展开换成一次 FFT;不满足自动回退并说明 | 1°×203 历元 **~10 s → 0.30 s**(nmax=60);与直接法逐点一致(相对 1e-14) |
| **水平形变 u_N / u_E** | 载荷勒夫数 `l′` 早就随包,补上球面梯度算子;矢量 = 北/东 + 大小 + 方位角 | 解析锚点 `C₁₀` 偏差 **0.0**;极点 `u_E = −√3` 精确;直接 ≡ FFT 7e-15 |
| **趋势 / 周年场** `series-fit` | 在**系数域**拟合(线性算子与空间基可交换) | 与场域逐点拟合一致到 **1e-15** |
| **区域平均** `series-basin` | 流域/区域平均时间序列;两种口径都算并对比;掩膜可给数组或网格文件 | 同网格下两口径**代数恒等**(6e-16…5e-15);`coeff` 比 `spatial` 快 **48×** |
| **去均值三口径** | **GRACE 惯例(2004–2010 平均)/ 全时段 / 自定义时段** 三选一;界面下拉 + 命令行 `--remove-mean-mode` | 三种口径的 EWH 差最大 **848 mm**、RMS 65 mm(与信号同量级);`all` 与旧 `--remove-mean` **逐位一致** |
| **动画 / GIF** | `series-synth --anim-out`;界面新增『动画』页(播放/暂停/逐帧/帧率/导出) | 帧数 = 历元数;GIF 只需 Pillow;同一输入两次导出**逐字节一致** |
| **界面** | 时间轴控件 + 历元范围 + 批量序列 + 去均值口径 + 时间序列/水平形变/动画/逐历元诊断四个新页签 | 离屏冒烟 **241 项**全绿 |

**一处必须知道的 legacy 坑**(软件会打印实际窗口,但**不会替你改数**):
你 legacy 脚本里的 `dur_mascon` 与它自己的注释对不上 ——
`read_GRACE_SH_preprocess_postprocess_SH60.m` 写着 `%% remove the mean of
2004-2010` 却用 `dur_mascon = 90:150`,在 CSR RL06(203 历元)上实测落到
**2009-12..2016-01**(差 6 年);同位置 GRACE-FO 版用 `19:90`,对应
2004-01..2009-12。所以 v2.0 **按日期**定口径;要复刻 `19:90` 用
`--remove-mean-mode custom --mean-from 2004-01-01 --mean-to 2009-12-31`。
详见方案 §4.4.2 与 `docs/probes/_probe_demean.py`。

**两个必须知道的"陷阱诊断"**(软件会主动报,但**不会替你改数**):

1. `GSM` 文件的 `C₀₀` 通常是 1 → 换成 EWH 会出现 **1.17e7 m** 的常量偏移;
2. 更普遍的是**静态场压过时间变化**(`C₂₀ ≈ −4.8e-4` → 换成 EWH 约 4 万米)。
   实测直接批量综合得到的逐历元 RMS 是 53 828 m;加 `--remove-mean` 后是
   物理合理的 **38–153 mm**。做异常场/时间序列请先去掉参考历元或时间均值。

**兼容性**:v1.0 的全部行为保持不变 —— `synth`/`info`/`convert` 的数值与界面约定
一条没动,8 套旧测试(598 项)仍然全绿。

除新增功能外,v2.0 还**修掉了两个此前静默失效/直接不可用的缺陷**:
CLI 自检里与 SHKit 的跨软件比对(路径插错,`import shkit` 必然失败),
以及冻结版 `--cli` 在 cmd 里会抛 `OSError: [Errno 22]` 并挂住(详见 §3.1)。

## 1. 这是什么

SHSynth 做球谐**综合**(synthesis)这一个方向:

```
输入:球谐系数 + 网格或散点位置
输出:网格或散点值 + 图
```

它与同课题组的 **SHKit**(做"散点/网格 → 系数"的分析方向)配对使用,
并且两边**逐位一致**:同一套系数、同一批点,本软件的输出与 SHKit 的
`synthesis` 完全相同(实测最大差 `0.0`),所有系数文件**双向兼容**。

## 2. v1.0 功能一览

### 2.1 系数读取:适配 SHKit 的全部输出格式

| 布局 | 扩展名 | 判据 |
| --- | --- | --- |
| `triangle` | `.sh .txt .csv .dat .tsv`(+`.gz`) | `#` 头含 `ncoef_triangle`,行数 = `2*(L+1)(L+2)/2` |
| `gmfcsv` | `.csv .txt .dat .tsv` | 表头 `n,m,C,S`,或前两列是合法 `(n,m)` 整数对 |
| `gfc` | `.gfc`(+`.gz`) | 首列 `gfc`/`gfct`(ICGEM/GFZ) |
| `npy` | `.npy` | `(2,L+1,L+1[,ntime])`;也接受 `(L+1,L+1[,ntime])` 与三角 `(2*NC[,ntime])` |
| `npz` | `.npz` | `C`/`S`/`meta`;也接受 `flat_cs` / `triangle` |

另外还能读:MATLAB 稠密方阵文本、`.gz` 压缩文本/gfc、中文表头、
`# key = value` 头里的物理量标签与高斯半径。

**写入**:五种布局都能写,写出的文件 SHKit 也能读回(实测逐位相同;
唯一例外是 `gmfcsv` 文本会因 pandas 解析丢最后 1 ulp,Python 原生读取无损)。

### 2.2 求值位置

* 全球网格 / 范围网格(任意矩形)
* **借用已有网格文件**的格点(netCDF、Surfer ASCII `.grd`、Esri ASCII、
  `.npy`、三列文本;**按内容判型**,GMT 的 `.grd` 其实是 netCDF 也能认)
* 散点文件(自动识别经纬度列;界面里是下拉框,含「自动(留空)」选项)
* 确定性 Fibonacci 球面散点

### 2.3 物理量与平滑

* 高斯平滑(逐阶 `Wₙ`,在综合时施加,**不改动系数文件**;`glq` / `frc`)
* 物理量换算:geoid / EWH / 面密度 σ / 径向形变 u_r —— **逐阶**因子
  (`Aₙ` 从 `1.17e7` 到 `1.68e8`),标签不明时**拒绝换算**而不是给错 1e7 倍的值
* 载荷勒夫数表随包(PREM / Wang 2012,`k′₁` 含 CE→CF 改正)

### 2.4 输出与绘图

* 网格:`.nc`(CF + 元数据)、`.grd`(Surfer ASCII)、`.npy`、三列 `.csv/.txt`
* 散点:`.csv/.txt/.dat/.tsv/.npy`
* 系数再导出:截断/平滑后的系数按五种布局另存
* 图:四联报告图 / 地图 / 逐阶谱 / 数值分布(或不出图),可叠加等值线
* **地图只画海岸线、不画国界**(避免主权划线争议)
* **自动聚焦**:区域结果自动缩放到结果范围,一键在"区域 / 全球"之间切换
* 图与界面显示的是**同一张** Figure(存盘与所见一致)

### 2.5 界面与命令行

* 桌面界面(PySide6):五组参数面板 + 五个页签 + 后台线程 + 进度/停止 + 拖放
* 命令行:`synth` / `info` / `convert` / `formats` / `selftest`
* 「关于 / 作者信息」含作者、单位、邮箱、电话、公众号二维码与 6 步快速上手
* 帮助菜单(F1)打开随包的 HTML 使用说明

### 3.1 修掉的一个会让 `--cli` 直接不可用的缺陷

**发行版是 windowed(GUI)exe**(`console=False`,双击开界面)。在 cmd/PowerShell 里跑

```bat
SHSynth.exe --cli series-basin --coeffs DIR --mask M.npy --out out.csv
```

时,进程**没有接上父控制台**,`sys.stdout` 是个非 `None` 但**无效**的句柄,
于是 `print()` 抛

```
OSError: [Errno 22] Invalid argument
```

**结果**:命令在打印标题(还没开始算)时就崩,用户只看到一堆调用栈;
而且进程不会自己退出(实测有两个残留进程挂了几个小时)。
`series-synth` / `series-read` / `info` 等所有 `--cli` 子命令都中招,
只是打包脚本自己用重定向(`> log 2>&1`)跑,句柄有效,所以一直没暴露。

**修法(两层)**:

1. `packaging/shsynth_launcher.py`:`--cli` / `--self-test` / `--version` / `--help`
   这几种模式启动时,先判 `GetStdHandle`/`GetFileType`,无效就
   `AttachConsole(ATTACH_PARENT_PROCESS)` 并把 `sys.stdout`/`stderr`
   **重开**到 `CONOUT$`(编码按控制台当前代码页选,不擅自改用户代码页)。
2. `shsynth/cli.py`:`_out()` / `_hr()` / `_out_err()` 改成**尽力而为** ——
   写不出去只记录、绝不抛异常。写不出去的文本会在退出前落到
   `%TEMP%\SHSynth_cli_output.txt` 并回报路径("算出来了但一句都没打出来"
   是最难排查的情况)。**计算成功就不该被一次打印连坐**:成功路径的返回码仍是 0。

**实测**(冻结版,不重定向,`Start-Process -Wait`):

| | 修之前 | 修之后 |
| --- | --- | --- |
| 退出码 | 1 / 2 + 调用栈 | **0** |
| 结果文件 | 没有 | **写出**(203 行,数值与源码运行一致) |
| 残留进程 | 有(挂住) | **无** |
| 动画 GIF | — | 写出 716 283 B,与源码运行的 GIF 帧数/尺寸/时长/循环**全一致** |

回归测试:`test_workflow_cli.py` 新增"控制台输出不许把命令带走"(7 项)。

### 3.2 安装路径含空格:产品没问题,但**校验**以前从没测过

发行程序装到含空格的路径下能不能跑?这是个必须验的问题 —— 用户机器上太容易
出现了:Windows 用户名带空格 → `%LOCALAPPDATA%` 就有空格 → 按用户安装的默认
路径就有空格;或者用户选"为所有用户安装" → `C:\Program Files\SHSynth`。

**实测结论:产品本身没问题**,但**构建脚本的安装校验以前装到
`%TEMP%\SHSynth_verify`(没有空格),等于从来没验过这种情况**。已补齐。

手工全流程实测(装到 `...\AppData\Local\SHSynth Space Test\深 目录`,空格 + 非 ASCII):

| 检查 | 结果 |
| --- | --- |
| 静默安装 | 退出码 0 |
| `--self-test` | **78 项通过**,退出码 0 |
| `--version` / `--cli`(真实解算) | 退出码 0,结果文件写出 |
| GUI 启动 | 正常驻留(12 秒未退出) |
| 开始菜单 / 桌面 / 使用说明 / 卸载 4 个快捷方式 | 目标 + 参数(`--guide`/`--version`)全对 |
| **通过桌面快捷方式启动** | 成功 |
| 卸载 | 退出码 0,目录清空 |
| 绿色版 zip 解压到同种路径 | 自检 78 项、`--version` 均正常 |

现在这些检查**每次构建都会跑**(`-VerifyInstall` 默认装到含空格的
`%LOCALAPPDATA%\SHSynth verify 验证目录`),并且新增了第 9 套测试
`test_packaging.py` 盯着这些约定。

**顺带查清了两个反直觉的点**:

1. **Inno 的 `[Run]`/`[Icons]` 的 `Filename` 里不能自己加引号**。试着手写
   `Filename: """{app}\SHSynth.exe"""` 会被编译器直接拒掉:
   `Parameter "Filename" cannot include quotes (")` —— 也就是说**含空格路径由
   Inno 内部处理**,脚本保持 `Filename: "{app}\SHSynth.exe"` 才正确。
   (用探针安装程序实测:含空格路径下 `[Run]` 能正常启动目标程序。)
2. **`build_installer.ps1` 的 BOM 会被不带 BOM 的编辑器悄悄吃掉**,而这个脚本
   必须有 BOM(Windows PowerShell 5.1 否则按 GBK 读中文注释,报的是
   "看起来毫不相干"的语法错误)。这一条现在由 `tools/check_packaging.py`
   在构建前置检查里守着。

## 5. 已知限制

1. **只做综合**。要做"散点/网格 → 系数"的分析,用 SHKit。
2. **Surfer 二进制 `.grd`**(首行 `DSRB`)不支持 —— 请在 Surfer 里
   「网格 → 转换」另存为 ASCII 或 netCDF。
3. **投影/平面坐标(米)的网格不能当经纬度用**:球谐综合在球面上做,
   软件会明确报错并给出出路(换成经纬度格点,或只借用它的数值、位置另给)。
4. **`.gfc` 一个文件只装一个时次**:多时次对象写 `.gfc` 必须指定时次,
   否则报错;多时次请用 `triangle` / `npz`。
5. **散点/网格文本输出默认 10 位有效数字**(与 SHKit 一致);系数文本用
   `%.17g`(任意 double 十进制往返无损)。
6. **HDF5 在网络盘上可能打不开 netCDF**(实测本机华为家庭存储映射盘如此)。
   软件会自动改用本机临时文件中转并在警告里说明。
7. 界面字体依赖**系统**中文字体(不随包分发字体)。
