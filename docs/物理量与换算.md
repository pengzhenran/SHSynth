## 1. 为什么必须区分物理量

GRACE Level-2 公布的 ``C_nm, S_nm`` 是**无量纲重力位系数**。要从它得到有物理
意义的量,要乘一个**逐阶**因子;而这些因子不是常数 —— 它们随阶数增长,而且不同
物理量增长方式不同:

| 目标 | 由 ``C_nm`` 出发的逐阶因子 | 需要 |
| --- | --- | --- |
| `geoid` 水准面 ΔN | **``R``(常数,不逐阶)** | — |
| `surface_density` 面密度 σ | ``R·ρ̄/3 · (2n+1)/(1+k′ₙ)`` | `k′` |
| `ewh` 等效水高 | ``Aₙ = R·ρ̄/(3ρ_w) · (2n+1)/(1+k′ₙ)`` | `k′` |
| `radial_displacement` 径向形变 u_r | ``R·h′ₙ/(1+k′ₙ)`` | `k′`、`h′` |

常数(与 SHKit 完全一致):

```
R       = 6378136.46 m        # 赤道半径(用于换算因子)
ρ̄       = 5517.0 kg/m³        # 地球平均密度
ρ_w     = 1000.0 kg/m³        # 水
```

推导(4π 归一化、``R = a``):

* 面密度谐波 ``σ_nm`` 产生的位谐波为 ``4πGa/(2n+1)·σ_nm``;
* 无量纲 Stokes 系数按 ``V = (GM/r)Σ(a/r)ⁿ C_nm Y_nm`` 定义,于是
  ``C_nm = 3(1+k′ₙ) / ((2n+1) ρ̄ a) · σ_nm``;
* 所以 ``σ_nm = ρ̄ a (2n+1) / (3(1+k′ₙ)) · C_nm``,``EWH_nm = σ_nm / ρ_w``;
* 水准面 ``N = Σ a C_nm Y_nm``,就是一个常数因子 ``a``;
* 径向位移 ``u_r = h′ₙ V_load / g``,化简为 ``u_{r,nm} = a h′ₙ/(1+k′ₙ) · C_nm``。

``u_r`` **向外为正**;``n≥2`` 时 ``h′ₙ`` 为负,所以正质量载荷对应地面下沉。

## 2. ``Aₙ`` 到底跨多少倍(实测)

用随包的载荷勒夫数表(PREM / Wang 2012)算出来的真实数值:

| n | ``Aₙ`` (EWH 因子) | 相对 ``A₀`` |
| --- | --- | --- |
| 0 | 1.172939e+07 | 1.00 |
| 1 | 3.429087e+07 | 2.92 |
| 2 | 8.440368e+07 | 7.20 |
| 3 | 1.021035e+08 | 8.71 |
| 4 | 1.218319e+08 | 10.39 |
| 5 | 1.440902e+08 | 12.28 |
| 6 | 1.675968e+08 | 14.29 |

**0 → 6 阶就跨了 14.29 倍**,而且它像 ``n`` 一样继续增长。三点结论:

1. 两套系数(位系数 与 EWH)**既不能相加,也不能比较**;
2. **不存在**"乘一个常数"就能互换的办法;
3. 重复乘一次 ``Aₙ`` 会放大 ``1e7``~``1e8`` 倍 —— 而且图还是很好看,
   所以软件必须**主动拦截**这种错误。

复现:`python -m shsynth info --coeffs model.gfc --unit-table`,或

```python
from shsynth.units import degree_factors
degree_factors("ewh", 6)
```

## 3. σ 与 EWH 是同一个量,只差常数

```
σ = ρ_w · EWH          (ρ_w = 1000 kg/m³)
```

它们的系数只差**常数 1000**(不是逐阶因子)。实测比值
`f_σ / f_EWH = 1000.0000000000`。与**位系数**之间才是逐阶的。

## 4. 软件怎么防止乘错

SHSynth 的框架是"两条公式、一个中间量、两个场":

```
正变换(由系数声明的『输入是』决定):  C_nm = a_nm / f_u
反变换(综合,永远如此):              场 = Σ (C_nm · f_t) · P̄_nm Y_nm
```

* **`field_unit` 标签**决定能换算成什么。`.gfc` 文件会被自动标成
  `geopotential`(ICGEM/GFZ 定义如此);三角布局文件会把头里的
  `field_unit = …` 读回来;
* 标签是 `scalar` / 未声明时,**要 EWH 会直接报错**并解释为什么不能替你猜:

  > 换算到 EWH 的因子取决于起点 —— 位系数 → EWH 要乘 Aₙ(n=2 时 8.44e7),
  > 而 geoid → EWH 只要乘约 13.2,两者差整整一个地球半径 R。

* **综合时换算**与**先把系数换算好再综合**结果逐位相同(测试覆盖),
  所以不存在"乘两次"或"漏一次";
* 径向形变的 `h′₀ = 0`,0 阶信息真的会丢 —— 软件把该阶置 0 并**如实告知**;
  反过来,一个自称是 `u_r` 却 0 阶明显不为 0 的系数集会被**拒绝反推**。

## 5. 高斯平滑:与换算正交

高斯平滑是**逐阶乘** ``Wₙ``(Jekeli/Wahr 公式),与物理量换算是两件互不相干的事,
可以同时用:

```bash
python -m shsynth synth --coeffs model.gfc --global-grid 1 \
    --gaussian-km 300 --target-unit ewh --out out/ewh.nc
```

要点:

* ``W₀ ≡ 1``(强制单位增益),所以**全球平均不变**;
* 半径是相对 ``nmax`` 才有意义的:.gfc 里 `nmax=12` 时 300 km 只压掉约 1%,
  1000 km 压掉 12%,3000 km 压掉 44%;
* 综合时施加的平滑**不改动系数文件**;想连系数一起存,用 `--out-coeffs`。

实测(`tests/test_units_filters.py`):

| 项目 | 结果 |
| --- | --- |
| ``W₀`` | 1.0(逐位) |
| 500 km 后场的标准差 | 降到 0.85 倍 |
| 1000 km | 0.58 倍 |
| 2000 km | 0.27 倍 |
| 平滑后全球平均的变化 | ``< 1e-5``(只是离散误差) |
