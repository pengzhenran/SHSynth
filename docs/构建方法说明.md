# SHSynth 打包环境与构建方法

> 目标:从源码到 **`SHSynth_Setup_v1.0.exe`**(一个自带 Python 运行时的安装程序)。
> 终端用户不需要装 Python;构建机需要一次性的极简环境。
> 与同课题组 SHKit 的 `packaging/BUILD_ENV.md` 同一套做法。

---

## 0. 一页速查

```powershell
# 1) 建极简环境(uv,Python 3.12,只有运行所需的包)
uv venv --python 3.12 D:\SHSynth_build\venv
uv pip install --python D:\SHSynth_build\venv\Scripts\python.exe `
    numpy scipy matplotlib PySide6-Essentials pandas xarray netCDF4 openpyxl pyinstaller

# 2) 出图标(改设计后要重跑)
python tools\make_icon.py                 # → SHSynth.ico + docs\SHSynth_icon_preview.png
# 3) 生成说明书与版本资源
python tools\make_help_html.py            # → docs\使用说明.html + docs\使用说明_img\
python packaging\make_version_info.py     # → packaging\version_info.txt

# 4) 一键:PyInstaller → 校验 → 冻结版自检 → Inno Setup → 安装-校验-卸载
powershell -ExecutionPolicy Bypass -File packaging\build_installer.ps1 -VerifyInstall
```

产物:

```
D:\SHSynth_build\dist\SHSynth\              目录包(绿色版)
D:\SHSynth_build\dist\SHSynth_Setup_v1.0.exe  安装程序
D:\SHSynth_installer\                       交付目录(安装程序 + 绿色版 zip + 图标)
D:\SHSynth_build\logs\selftest.log          冻结版自检日志
```

**中间产物一律放在项目外的 `D:\SHSynth_build\`**:项目在网盘同步目录里,
同步驱动会锁文件(PyInstaller 清理时报 `PermissionError: WinError 32`),
而且 HDF5 在这个网络盘上写不出 netCDF(`Errno 13`)。

## 1. 极简环境怎么建(为什么用 uv 而不是 conda)

```powershell
uv venv --python 3.12 D:\SHSynth_build\venv
uv pip install --python D:\SHSynth_build\venv\Scripts\python.exe `
    numpy scipy matplotlib PySide6-Essentials pandas xarray netCDF4 openpyxl pyinstaller
```

要点:

| 决定 | 原因 |
| --- | --- |
| **uv** 而不是 conda | uv 建的 venv 秒级、默认不带 pip/测试框架,天然"极简";Python 3.12 由 uv 管理,不污染 Anaconda |
| NumPy/SciPy 走 **PyPI(OpenBLAS)** | Anaconda 版 NumPy 带 Intel MKL(`mkl_*.dll` ~520 MB),目录包会从 ~300 MB 涨到 1.3 GB |
| PySide6 装 **PySide6-Essentials** | 完整 `PySide6` 会带 `PySide6-Addons`,里面 **Qt Charts / Qt Data Visualization / Qt Graphs 是 GPL-only**,闭源分发直接不可能 |
| 不装 pytest/pyflakes | 测试用标准库跑(`tests/run_all.py`),不需要额外依赖;需要静态检查时在**源码环境**里装 pyflakes 即可 |
| `openpyxl` | 读 `.xlsx` 散点文件用(pandas 的 Excel 后端) |

装完自检(必须"不存在"才是对的):

```powershell
D:\SHSynth_build\venv\Scripts\python.exe tools\check_licensing.py
#   [通过] 未检测到 GPL-only 模块 -> 当前环境可用于闭源分发
```

实测环境(2026-09):

| 组件 | 版本 |
| --- | --- |
| Python | 3.12.13(uv 管理) |
| numpy / scipy | 2.5.3 / 1.18.1 |
| matplotlib | 3.11.2 |
| PySide6-Essentials | 6.11.2 |
| PyInstaller | 6.22.3 |
| Inno Setup | 6(`D:\Inno Setup 6\ISCC.exe`) |

## 2. 图标

`tools/make_icon.py` 用 matplotlib 画好各尺寸 PNG,再**手工按 ICO 容器格式打包**
(Vista 以后 `.ico` 允许直接内嵌 PNG 帧)—— 所以**不需要 Pillow**,打包环境更干净。

```powershell
python tools\make_icon.py
# 图标已写出: SHSynth.ico(7 个尺寸:256/128/64/48/32/24/16)
# 预览图已写出: docs\SHSynth_icon_preview.png
```

设计:球面 + 经纬网 + 红蓝异常瓣 + 深色描边 —— 一眼看出"球面 + 波动",
且 16×16 下仍能辨认(预览图里有小尺寸对照)。

换配色/换设计后重跑本脚本,`packaging\shsynth.spec`(exe 图标)与
`packaging\installer_shsynth.iss`(安装程序图标)都会自动用新的 `SHSynth.ico`。

## 3. 说明书

```powershell
python tools\make_help_html.py
```

把 `docs/` 下的 Markdown 合成**一份自包含 HTML**(`docs/使用说明.html`),
并把引用的图片拷进 `docs/使用说明_img/`。安装包把它打进 `_internal\docs\`,
界面「帮助 → 使用说明(F1)」与安装完成页的复选框都打开它。

> 转换器只支持本项目文档实际用到的 Markdown 子集(标题/表格/代码块/列表/引用/
> 图片/链接),**不引入 markdown 依赖**;生成后 `build_installer.ps1` 会校验
> "说明书里引用的图片是否都在包里",缺图就拒绝出包。

## 4. 一键盘安装程序

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build_installer.ps1 -VerifyInstall
```

它做四件事:

1. **PyInstaller** 按 `packaging\shsynth.spec` 打 onedir 目录包 →
   `D:\SHSynth_build\dist\SHSynth\`
   (入口是 `packaging\shsynth_launcher.py`,**不是** `shsynth/gui/app.py`);
2. **校验目录包**:说明书/配图/二维码/许可是否都在;说明书里的图片引用是否都能解析;
   启动一次 exe 确认不是"一闪就没";再跑 **`SHSynth.exe --self-test`**(52 项关键路径);
3. **Inno Setup** 编译 `packaging\installer_shsynth.iss` →
   `dist\SHSynth_Setup_v1.0.exe`(需要中文语言文件,脚本会自动装);
4. **(`-VerifyInstall`)**静默安装到临时目录 → 校验文件 → 再跑一次自检 →
   启动一次 → 卸载。

### 常用参数

| 参数 | 作用 |
| --- | --- |
| `-SkipBuild` | 复用已有目录包,只重编安装程序(改 `.iss` 后用) |
| `-SkipInstaller` | 只出目录包(绿色版),不编安装程序 |
| `-VerifyInstall` | 额外安装-校验-卸载一遍 |
| `-KeepConsole` | 出带控制台窗口的 exe(排错用) |
| `-Python X:\...\python.exe` | 换打包用的解释器(默认 `D:\SHSynth_build\venv\Scripts\python.exe`) |
| `-BuildRoot X:\path` | 换构建根目录(默认 `D:\SHSynth_build`) |
| `-FinalDir X:\path` | 换交付目录(默认 `D:\SHSynth_installer`) |
| `-Iscc X:\...\ISCC.exe` | 指定 ISCC 路径(默认自动找几个常见位置) |

### 冻结版自检(`SHSynth.exe --self-test`)

进程"活着"**不代表没崩**:崩在导入期时窗口根本不会出现,而 `Start-Process`
可能已经拿到进程句柄、`HasExited` 还是 `false`。所以冻结版必须自己走关键路径
并以退出码表态(`shsynth/selftest.py`,源码树里 `python -m shsynth.selftest` 同样能跑):

```
[PASS] 版本 1.0.0(SHSynth 球谐系数解算)
[PASS] numpy 2.5.3 / scipy 1.18.1 / matplotlib 3.11.2 / PySide6 6.11.2
[PASS] 载荷勒夫数 k′ 表(... 阶)         [PASS] 离线海岸线(... 顶点)
[PASS] 国界数据已移除(只画海岸线)      [PASS] 公众号二维码
[PASS] triangle/gmfcsv/gfc/npy/npz 往返逐位相同

[PASS] 综合时高斯 = 先平滑再综合         [PASS] 综合时换算 = 先换算再综合
[PASS] 网格 .nc/.grd/.npy/.csv 写出+回读一致
```

任何一项失败都会让打包脚本直接报错退出,不会把坏包交出去。

## 5. 发行包里有什么

```
SHSynth.exe                     程序本体
_internal\                      运行时(Python、Qt、numpy/scipy/matplotlib/xarray/netCDF4…)
_internal\shsynth\data\         载荷勒夫数表 + 离线海岸线 + 公众号二维码
_internal\docs\                 使用说明.html + 使用说明.md + 发行说明.md + 使用说明_img\
_internal\licenses\             LGPL-3.0 / GPL-3.0 / NOTICE(第三方声明)
LICENSE.txt                     MIT 许可
```

**只放终端用户用得上的东西**:说明书、发行说明、配图、许可。**不放**源码、
测试、构建脚本(`source\`、`README.md`、`构建方法说明.md`、`命令与参数.md`、
`物理量与换算.md`、`许可与第三方组件.md` 等一律不进包;要源码请向作者索取)。
`build_installer.ps1` 会**逐个核对**这份清单,发现多带了开发文档就直接报错。

**两种交付格式都要有许可正文**:

* 安装版:`LICENSE.txt` 由 `installer_shsynth.iss` 单独放进 `{app}`;
* 绿色版:zip 是直接压缩目录包,所以打包脚本会先把 `LICENSE.txt` 复制进
  `dist\SHSynth\`,再压缩 —— 否则 zip 里就只有 `_internal\licenses\` 里的
  第三方许可,少了本软件自己的 MIT 正文(MIT 要求许可随所有副本分发)。
  脚本最后会打开 zip 核对 `LICENSE.txt`、说明书、第三方声明都在,且没混进源码。

**不进包**:`out\`(运行产物)、`__pycache__`、测试用的临时目录。

## 6. 踩过的坑(都已在脚本/spec 里修好)

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| **exe 双击一闪就没**,报 `attempted relative import with no known parent package` | PyInstaller 把**入口脚本**当顶层脚本执行(没有父包)。入口原本是 `shsynth/gui/app.py`,里面的 `from .. import __version__` 找不到父包 | 入口改成包外的 `packaging/shsynth_launcher.py`:先 `import shsynth.gui.app`(包被正常导入)再调用 |
| PyInstaller 中止:`attempt to collect multiple Qt bindings` | 打包环境里同时有 PySide6 与 PyQt5/PyQt6 | `shsynth.spec` 的 `ALWAYS_EXCLUDE` |
| 目录包 1.3 GB | Anaconda 版 NumPy 带 Intel MKL(`mkl_*.dll` ~520 MB) | 用 uv/PyPI 的 NumPy(OpenBLAS),目录包 ~100 MB 量级 |
| `ISCC ... 系统找不到指定的文件` | `.iss` 里的相对路径按脚本所在目录解析;项目路径含中文 | 用 `/DProjDir=... /DBuildRoot=...` 传绝对路径 |
| `build_installer.ps1` 中文乱码、解析报错 | Windows PowerShell 5.1 把无 BOM 的 UTF-8 当 GBK 读 | 脚本存成 **UTF-8 with BOM**(本仓库已是) |
| 安装向导只有英文 | Inno Setup 官方包**不带** `ChineseSimplified.isl` | 仓库里带 `packaging/languages/ChineseSimplified.isl`(精简版,只覆盖主流程,版本兼容),构建脚本自动装到 `<Inno Setup>\Languages\` |
| 自检日志中文乱码 | 冻结版(windowed)的 stdout 是 GBK 管道 | 自检里 `sys.stdout.reconfigure(encoding="utf-8")`;打包脚本也设 `PYTHONIOENCODING=utf-8` |
| 帮助菜单打开是空图 | `docs/` 没进包,或图片没跟着进 | spec 的 `datas` 带 `docs/`;打包脚本校验说明书里的每个 `src=` 图片都存在 |
| 装完启动崩、报 `DLL load failed` | 打包环境里混入了 conda 的 Qt6/UCRT | 用 uv/venv 环境,全走 PyPI;`excludes` 掉其它 Qt 绑定 |
| 绿色版 zip 里没有本软件的 `LICENSE.txt` | 安装版由 `.iss` 单独放许可,而 zip 是直接压缩目录包 —— 目录包里本来就没有它 | 打包脚本在压缩前把 `LICENSE.txt` 复制进 `dist\SHSynth\`,并按条目核对 zip |
| 说明书里每张图下面多出半张图高的空白 | Qt 的 QTextBrowser 把**块级** `line-height`(1.5)也乘到行内图片的高度上:475px 的图,行框被撑到约 715px | `make_help_html.py` 给"整段只有图片"的段落加 `class="pic"`,`p.pic { line-height:100% }`;表格里的二维码单元格同样处理。`tests\test_gui_smoke.py` 量"图底到下一块"的距离,>60px 就报错 |
| 同一套测试连跑两遍,第二遍偶尔 `PermissionError` | 项目在网络盘(华为家庭存储映射盘)上,SMB 上上一个进程的句柄还没释放 | `tests\_common.py` 的 `tmp_dir()` 每个子目录**本进程首次**用时先清空,写入操作对 `PermissionError` 重试 4 次 |
